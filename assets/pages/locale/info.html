Información general

¿Para qué tenemos .pot y .po?

Podemos verlo como una cadena de producción:

             DESARROLLO
                 │
                 ▼
        textos originales
                 │
                 ▼
     notification-center.pot
          plantilla maestra
                 │
       ┌─────────┼─────────┐
       ▼         ▼         ▼
      de        it        ko ...
       │         │         │
       ▼         ▼         ▼
     .po       .po       .po
       │         │         │
       │      traducción   │
       │         │         │
       └─────────┼─────────┘
                 ▼
              .mo
          compilación
                 │
                 ▼
        programa en ejecución

Una analogía sencilla:

Archivo Podemos pensarlo como
.pot Formulario/plantilla maestra
.po Formulario rellenado para un idioma
.mo Formulario convertido a un formato que la aplicación puede consultar rápidamente

¿Y por qué no tenemos español?

Actualmente tenemos:

de/
it/
ko/
nl/
pero no: 
es/

Eso significa simplemente que el repositorio no tiene una traducción española dentro de esta estructura. No significa necesariamente que la extensión no pueda funcionar en un sistema en español.

Si no encuentra una traducción para un msgid, gettext normalmente termina utilizando el texto original.

Por ejemplo:
_("Clear")
si no existe traducción:
Clear
Si existe traducción:
Clear → Limpiar

Un detalle importante

No debemos asumir todavía que para agregar español simplemente habría que crearlo y listo.

locale/

    es/
        notification-center.po

Hay que estudiar cómo se construyen/instalan las traducciones en este proyecto, dónde espera GNOME encontrar los .mo, y cómo se relaciona eso con:

imports.gettext.domain("notification-center")

Pero eso ya sería el siguiente nivel de investigación, por ahora, para nuestro objetivo actual, creo que la distinción fundamental queda así:

.pot = qué cosas se pueden traducir.
.po = cómo se traducen esas cosas para un idioma concreto.
.mo = la traducción compilada que la aplicación utiliza.

¿Qué ocurre cuando la extensión funciona?

Aquí podemos conectar esto con algo que acabamos de estudiar en extension.js.

Tenemos:

const _ = imports.gettext
    .domain("notification-center")
    .gettext;

y después aparecen cosas como:

_("Clear")
_("No Notifications")

La extensión está diciendo, en esencia:

"Busca una traducción para este texto dentro del dominio notification-center."

El flujo conceptual sería:

extension.js
     │
     │ _("Clear")
     ▼
gettext
     │
     │ dominio:
     │ "notification-center"
     ▼
idioma actual del usuario
     │
     ▼
traducción correspondiente
     │
     ▼
"Clear" → traducción

Y aquí entran los .mo.
