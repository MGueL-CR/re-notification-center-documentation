¿Qué es extension.js?

Es el punto de entrada. Sería el equivalente a:

En C:

main()

En Java:

public static void main()

GNOME ejecuta este archivo cuando:

  • habilitas la extensión;
  • deshabilitas la extensión;
  • inicia GNOME Shell.

Aquí viven las funciones principales:

enable()
disable()

Y, dependiendo de la versión de GNOME, también una clase Extension.

Estructura general

El archivo parece seguir este orden:

Imports
    │
    ▼
Variable global
    │
    ▼
Funciones auxiliares
    │
    ▼
Clase principal

Todavía no hemos visto el código, pero esa es la arquitectura típica de una extensión. Y ese orden me gusta. No es un archivo escrito "como salió". Tiene una organización.

¿Por qué declarar primero: 
let notificationCenter = null;
en lugar de escribir simplemente: 
let notificationCenter = new NotificationCenter();

Porque la extensión no puede crear el objeto apenas se carga, esa respuesta la descubriremos cuando veamos enable().

Debe esperar a que GNOME le diga:

"Ahora sí, habilítate."

Y en ese momento probablemente haga algo parecido a:

notificationCenter = new NotificationCenter();

Y cuando GNOME diga:

"Desactívate."

Hará:

notificationCenter.destroy();
notificationCenter = null;
