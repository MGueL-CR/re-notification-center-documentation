¿Qué es schemas/?

Aquí vive la configuración permanente, suelen estar los esquemas de GSettings (.gschema.xml), que también pertenecen a la extensión.

Lo habitual es:

re-notification-center@mguel-cr/    
    ├── schemas/    
    │   
    └── org.gnome.shell.extensions....gschema.xml

Todo eso se guarda mediante GSettings.

El archivo XML define:

  • nombre de la opción;
  • tipo;
  • valor por defecto;
  • descripción.

Podríamos decir que es la "base de datos" de preferencias de la extensión y, honestamente, creo que este archivo será mucho más entretenido de lo que parece.

¿Por qué? Porque hasta ahora nosotros conocimos las preferencias desde el código.

Por ejemplo:

this.prefs.get_boolean("show-label");
Nosotros aprendimos:
Existe una preferencia llamada show-label.

Pero nunca vimos:

  • cuál es su valor por defecto;
  • su tipo;
  • su descripción;
  • quién la define.

El archivo XML responde justamente eso.

<key name="show-label"
     type="b">

Vamos a encontrar cosas como estas y podremos decir:

"¡Ah! Aquí nació esa preferencia."

Y tengo la sensación de que este archivo será como leer el "acta de nacimiento" de la extensión. Ya conocemos a todos los personajes (show-label, autohide, blink-time, sections-order...), ahora solo falta conocer dónde fueron registrados oficialmente. ¡Zarpemos hacia gschema.xml!

Dinámica para este nuevo capítulo.

En extension.js fuimos método por método porque era la forma natural de entender la lógica. Con el gschema.xml creo que podemos hacerlo de otra manera: clave por clave.

Por cada <key> veremos:

  1. Nombre (show-label, autohide, etc.).
  2. Tipo (b, i, s, as, enum...).
  3. Valor por defecto.
  4. Dónde la vimos usar en extension.js.
  5. Qué efecto produce en la extensión.

Así, no solo leeremos un XML, sino que construiremos el puente entre la configuración y el comportamiento que ya conocemos.

Antes de entrar al contenido:

Hay algo que quiero destacar. Este archivo tiene dos grandes bloques.

Definiciones de enumeraciones (enum)

Aquí Selenium-H crea sus propios tipos.

Por ejemplo: <enum id="...events-position"> Es decir:

"Esta preferencia no aceptará cualquier número. Solo estos valores."

El <schema>

Aquí vive la configuración propiamente dicha.

Cada: <key ...> equivale a una preferencia que luego vimos en: this.prefs.get_boolean(...) o this.prefs.get_int(...)

Un pequeño diccionario

Porque vamos a verlo muchas veces, quiero crear un pequeño "diccionario".

Tipo Significado
b Boolean (true / false)
i Integer
d Double
s String
as Array de Strings
enum Enumeración definida arriba

Con esto ya podremos leer cualquier clave sin detenernos a pensar qué significa el tipo.

Regla rápida para identificar tipos de Arrays

a + tipo
│
├── as → array de strings
├── ai → array de integers
├── ab → array de booleans
└── ad → array de doubles

Y esto sigue la misma lógica que los tipos simples que ya vimos:

s  → string
i  → integer
b  → boolean
d  → double

Así que cuando encontremos algo como: type="as" ya podemos identificarlo inmediatamente como una lista/arreglo de Strings, sin tener que buscarlo.

Entonces, la misma lógica que acabamos de ver con: type="as" se aplica a ai:

a = array
i = integer

Por lo tanto: type="ai" significa:

arreglo de enteros (array of integers)

Por ejemplo: <default>[1, 2, 5, 8]</default> sería una lista de cuatro enteros.

Capítulo 2: Las claves.
