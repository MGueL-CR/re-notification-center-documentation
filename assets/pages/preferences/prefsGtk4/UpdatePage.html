UpdatePage

Esta clase es diferente a las anteriores porque no hereda de nuestra clase base de preferencias, sino directamente de Gtk.ScrolledWindow.

Se crea una nueva clase GObject.

const UpdatePage_NotificationCenterExtension = new GObject.Class({ ... })

Name

El nombre interno de la clase.

Name: 'UpdatePage_NotificationCenterExtension',

Extends

Aquí tenemos una diferencia importante respecto a las páginas anteriores.

Extends: Gtk.ScrolledWindow,

La jerarquía es:

UpdatePage_NotificationCenterExtension
            │
            ▼
     Gtk.ScrolledWindow

No pasa por: PrefsWindow_NotificationCenterExtension

Tiene sentido porque una página de actualización no necesariamente necesita los métodos auxiliares de configuración que tiene nuestra clase base.

_init(profilesObject)

_init: function(profilesObject) {
  
    this.parent();
    this.profilesObject = profilesObject;
    
}

Primero: this.parent();

Inicializa el Gtk.ScrolledWindow heredado.

Después: this.profilesObject = profilesObject;

Aquí aparece una nueva propiedad de instancia: profilesObject y recibe directamente el parámetro que llega al constructor.

Por ahora sabemos solamente:

profilesObject
└── objeto recibido desde quien crea UpdatePage

No vamos a asumir todavía qué contiene, pero hay una pista interesante:

Recordemos que anteriormente encontramos en Prefs_NotificationCenterExtension:

let updatePage = new UpdatePage_NotificationCenterExtension(this.profilePrefs);

Así que, siguiendo el código que ya vimos:

Prefs_NotificationCenterExtension
        │
        │ crea
        ▼
UpdatePage_NotificationCenterExtension
        │
        │ recibe
        ▼
this.profilePrefs
        │
        ▼
profilesObject

Esto nos deja una pregunta muy concreta para cuando aparezcan las siguientes funciones:

¿Qué hace UpdatePage con profilesObject?

Eso sí lo podremos responder directamente viendo su uso.

displayPrefs: function()

Aquí ya vemos claramente qué papel cumple UpdatePage: es una página informativa que aparece después de una actualización y ofrece al usuario la posibilidad de restablecer las preferencias.

Contenedor principal

Crea el contenedor principal de la página.

this.vbox = new Gtk.Box({
    orientation: Gtk.Orientation.VERTICAL,
    margin_top: 30,
    margin_end: 30,
    margin_bottom: 30,
    margin_start: 30
});

Es un Gtk.Box vertical, por lo que los elementos se van colocando uno debajo de otro:

┌─────────────────────────────┐
│          imagen             │
│                             │
│        versión              │
│                             │
│       información           │
│                             │
│     botón de reset          │
└─────────────────────────────┘

Y los cuatro márgenes son de 30.

Contenedor e imagen

let imageBox = new Gtk.Box({
    halign: Gtk.Align.CENTER

    file: Extension.dir.get_child('eicon.png').get_path(),

Busca: eicon.png dentro del directorio de la extensión y crea una imagen de 96 × 96 aproximadamente.

Luego: imageBox.append(image); La imagen queda centrada mediante imageBox.

Etiqueta de versión

this.versionLabel = new Gtk.Label({
    halign: Gtk.Align.CENTER,
    wrap: true,
    justify: 2,
    use_markup: true,
    label: "" + _("Extension is upgraded to Version  ") + Metadata.version

Aquí se guarda como propiedad de instancia: versionLabel.

El texto informa:

Extension is upgraded to Version X

Donde X viene de: Metadata.version.

Por ejemplo, si la versión fuera 23.03:

Extension is upgraded to Version 23.03

Información sobre el reset

Esta es la explicación que recibe el usuario.

this.firstInfo = new Gtk.Label({
    halign: Gtk.Align.CENTER,
    wrap: true,
    justify: 3,
    use_markup: true,
    label: "\n\n" +
        _("A Reset to default preferences is needed for upgrading to this version. Please Reset the extension by clicking the button below.") +
        "\n\n"
});

La idea es:

Actualización
     ↓
las preferencias necesitan ser reiniciadas
     ↓
usuario pulsa Reset

Y esto conecta directamente con la clase que ya analizamos: ExtensionResetButton

Crea el botón de reset

Aquí tenemos una conexión interesante.

this.resetExtensionButton =
    new ExtensionResetButton_NotificationCenterExtension(this);

Le pasa: this es decir, la propia instancia de: UpdatePage. Esto explica parcialmente el profilesObject que vimos en _init().

Recordemos:

_init: function(profilesObject) {

    this.parent();
    this.profilesObject = profilesObject;

},

En este caso el objeto que se pasa al constructor de UpdatePage era: 

new UpdatePage_NotificationCenterExtension(this.profilePrefs);

Pero este otro this que se pasa al botón es la página UpdatePage misma.

Esto nos da dos relaciones distintas que tendremos que seguir:

Prefs_NotificationCenterExtension
        │
        └── crea UpdatePage
              │
              └── profilesObject = this.profilePrefs
UpdatePage
    │
    └── crea ExtensionResetButton
          │
          └── recibe this = UpdatePage

Construye la jerarquía visual

imageBox.append(image);
this.vbox.append(imageBox);
this.vbox.append(this.versionLabel);
this.vbox.append(this.firstInfo);
this.vbox.append(this.resetExtensionButton);

El orden final es:

vbox
│

Finalmente

Introduce el vbox en el ScrolledWindow

this.set_child(this.vbox);

Como la clase extiende: Gtk.ScrolledWindow el vbox se convierte en su contenido.

Algo importante

Ya podemos afirmar que esta clase no realiza la actualización en sí. Su función, por lo que hemos visto hasta ahora, es presentar una página de aviso:

"La extensión fue actualizada; debes restablecer las preferencias para adaptarlas a esta versión."

Y reutiliza el mecanismo de reset que ya estudiamos.

El misterio de profilesObject todavía permanece, porque en esta función no se utiliza. Lo dejamos pendiente hasta encontrar dónde aparece this.profilesObject.

updateDone: function(mode)

Recibe un parámetro llamado mode.

updateDone: function(mode) { ... }

Si mode es false, no hace nada

if(mode == false) {
    return;
}

Es decir:

mode == false
    ↓
return
    ↓
no continúa

Por tanto, para que la actualización se marque como completada, mode debe ser un valor distinto de false.

Oculta el botón de Reset

this.resetExtensionButton.hide();

Recordemos que ese botón fue creado en displayPrefs():

this.resetExtensionButton =
    new ExtensionResetButton_NotificationCenterExtension(this);

Después de que el proceso termina correctamente:

Reset
  ↓
actualización completada
  ↓
ocultar botón

El usuario ya no necesita volver a ejecutar el reset desde esta página.

Y aquí aparece current-version

Este es un hallazgo importante para nuestro análisis anterior.

settings.set_double('current-version', Metadata.version);

Recordemos que en Prefs._init() encontramos:

if(settings.get_double("current-version") < 23.03) {
    let updatePage = new UpdatePage_NotificationCenterExtension(...);
    ...
}

Ahora podemos conectar ambos extremos:

                current-version
                     │
          ┌──────────┴──────────┐
          │                     │
          ▼                     ▼
   Prefs_Notification       UpdatePage
   Center._init()           updateDone()
          │                     │
          │ lee                 │ escribe
          ▼                     ▼
    get_double()            set_double()

El flujo histórico es:

Se abre preferencias
        │
        ▼
current-version < 23.03 ?
        │
       Sí
        ▼
se muestra UpdatePage
        │
        ▼
usuario hace Reset
        │
        ▼
updateDone(true)
        │
        ▼
current-version = Metadata.version

En la siguiente apertura:

current-version >= 23.03
        │
        ▼
no se muestra UpdatePage

Esto confirma algo

Anteriormente habíamos encontrado este código comentado en ExtensionResetButton:

//settings.set_int("current-version", Metadata.version);

Ahora vemos que el lugar donde realmente se actualiza current-version es UpdatePage.updateDone(), y además utiliza: settings.set_double() no set_int().

Eso es importante porque demuestra que current-version sí tenía un propósito funcional dentro del diseño original. No era simplemente un valor decorativo.
