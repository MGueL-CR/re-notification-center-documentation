keyVal.pop();
keyVal.push(nuevoValor);

Eso nos dice algo interesante sobre su supuesto modelo de datos:

keyVal
└── probablemente contiene un solo elemento

Porque está eliminando el último elemento y agregando uno nuevo.

Si hubiera: 
keyVal = ["A", "B", "C"]
entonces: 
keyVal.pop();
Eliminaría solamente "C".

No estaría reemplazando necesariamente el elemento que se está editando.

Por eso no debemos generalizar que keyVal siempre sea un array de un solo elemento solo por ver este código. Lo que sí podemos decir es:

prefStr() está diseñado para modificar el último elemento del array.

Y el hecho de que inmediatamente después use keyVal[0] al inicializarlo hace bastante probable que en el uso normal ese array tenga un solo elemento.

Ahora vemos finalmente el box

¡Aquí se entiende perfectamente por qué creó box!

box.append(SettingCombo);
box.append(new Gtk.Label({label: "  +  "}));
box.append(strSetting);

Los tres elementos se colocan horizontalmente:

┌──────────────────────────────────┐
│  [ ComboBox ]    +    [ Entry ]  │
└──────────────────────────────────┘

Por ejemplo, visualmente podría terminar siendo:

[ Firefox> ]  +  [ algo ]

El + es simplemente un elemento visual, no forma parte del valor almacenado. Y esto es importante:

ComboBox       +       Entry
   │                    │
   │                    │
   └─────── NO ─────────┘
           │
       el "+" no se guarda

El valor se construye mediante:

options[SettingCombo.get_active()] + strSetting.text

El " + " solo ayuda al usuario a entender que está combinando dos partes.

Finalmente

Aquí coloca toda la combinación en el Grid

this.attachLabel(KEY, pos);
this.attach(box, 1, pos, 1, 1);

Así que nuevamente tenemos:

         columna 0                 columna 1
┌────────────────────────┬──────────────────────────┐
│ summary de KEY         │ [ Combo ] + [ Entry ]    │
└────────────────────────┴──────────────────────────┘

Y esto reutiliza nuestro método anterior: attachLabel(KEY, pos);

Por lo que el nombre de la preferencia se obtiene automáticamente desde el summary del gschema.

settings.get_strv(KEY) como arreglo de strings

¿Cómo sabes que es un arreglo de strings y no solo un string?

Porque aquí intervienen dos cosas diferentes: el método que se está llamando y el tipo de la key en gschema.

La parte decisiva es: settings.get_strv(KEY)

get_strv() significa "string vector"

En GSettings, los métodos tienen nombres que indican el tipo de dato que recuperan:

get_boolean()  → boolean
        get_int()      → entero
        get_double()   → double
        get_string()   → string
        get_strv()     → vector de strings

Ese v de strv viene de string vector. Por eso: 

let keyVal = settings.get_strv(KEY);

keyVal es un array de strings.

Por ejemplo: let keyVal = settings.get_strv("name-list"); podría producir:

[
            "Firefox",
            "Thunderbird",
            "Rhythmbox"
        ]

Y por eso inmediatamente después el código puede hacer: keyVal[0] para acceder al primer string.

Y además

Tenemos la confirmación del gschema antes vimos:

<key name="name-list" type="as">

El tipo: as significa: as → array de strings

a  → array
        s  → string
        
        as → array de strings

Por tanto tenemos dos pistas independientes:

gschema
        type="as"
           │
           ▼
        array de strings
           │
           │
           ▼
        GSettings
        get_strv(KEY)
           │
           ▼
        array de strings

Y por eso esto: keyVal[0] tiene sentido.

¿Y qué pasa con get_string()?

Si fuera:

let keyVal = settings.get_string(KEY);

Entonces keyVal sería directamente: "Firefox" y esto: keyVal[0] no significaría "primer elemento del array".

En JavaScript, tratándose de un string, sería el primer carácter: 

"Firefox"[0]
             ↓
            "F"

Así que en este código:

let keyVal = settings.get_strv(KEY);
        keyVal[0]

Queda bastante claro que el autor está esperando un array/vector de strings. Y esto conecta muy bien con la pregunta que me hiciste anteriormente sobre:

type="ai" → arreglo de enteros.

Exactamente. La misma lógica:

ai → array de integers
        as → array de strings

Y ahora ya estamos viendo cómo esa definición del gschema se refleja directamente en el código JavaScript.
