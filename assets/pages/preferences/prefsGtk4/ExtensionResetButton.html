Nuestra conexión con gschema

Aquí está la parte más interesante:

settings.reset("show-media");
settings.reset("show-notification");
settings.reset("show-events");
settings.reset("events-position");
...

Esto confirma definitivamente que: settings es el objeto Gio.Settings que inicializamos al comienzo:

settings = ExtensionUtils.getSettings(
    "org.gnome.shell.extensions.notification-center"
);

Y: settings.reset("show-media"); significa:

Restablecer esa key al valor predeterminado definido por el schema.

Por ejemplo, nuestro gschema decía: 

<key name="show-media" type="b">
    <default>true</default>
</key>

Entonces: settings.reset("show-media"); hace que vuelva a: true

No está inventando el valor aquí, el valor predeterminado está en gschema. Y esto demuestra exactamente por qué fue tan útil estudiar primero gschema.

Una ausencia interesante

Observa que aquí no aparecen:

reload-signal
reload-profiles-signal
current-version

Eso tiene sentido. Esas keys las clasificamos como variables/señales internas de la extensión, no como preferencias del usuario.

El botón Reset está restableciendo: preferencias configurables no todas las keys existentes en el schema.

Esto es una distinción muy importante que ahora podemos confirmar con código real.

La línea comentada

Tenemos:

//settings.set_int("current-version", Metadata.version);

Esta línea merece quedar marcada como pendiente. Y además tiene relación directa con nuestra investigación anterior sobre: current-version Recordemos:

<key name="current-version" type="d">
    <default>23.00</default>
</key>

Aquí vemos que Selenium-H en algún momento consideró actualizar ese valor desde el botón Reset, pero actualmente está comentado.

Y además hay una pequeña inconsistencia que debemos revisar posteriormente: settings.set_int(...) mientras que el schema decía: type="d", d en GSettings es double, no entero.

No debemos concluir todavía si esto es simplemente código histórico, código incorrecto o si hubo un cambio de tipo en algún momento. Lo anotamos para investigación.

Cierra el diálogo y ejecuta callback

Después de resetear: dialog.destroy(); Y aparece algo muy interesante:

if(object[functionToBeCalledAtTheEnd]) {
    object[functionToBeCalledAtTheEnd]( parameter );
}

Recordemos los argumentos originales: this.resetExtension(object, "updateDone", null)

Por tanto, conceptualmente queda:

if(object["updateDone"]) {
    object["updateDone"](null);
}

Es decir:

Si object tiene un método llamado updateDone, ejecútalo pasando null.

Esto explica por qué el método recibe el parámetro: functionToBeCalledAtTheEnd

No es necesariamente una función directamente; es el nombre de un método que debe buscar dentro de object. Esto hace que resetExtension() sea reutilizable.
