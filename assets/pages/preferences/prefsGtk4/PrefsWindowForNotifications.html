adjustOtherSectionsKeepingThisKeyValueSame: function(KEY)

Esta función efectivamente nos empieza a revelar la lógica que hay detrás de show-media, show-notification y show-events, y además explica por qué esos valores son enteros.

    let currentKeyValue = settings.get_int(KEY);
    let currentSection = KEY.substring(5,KEY.length);

Aquí tenemos dos variables locales: currentKeyValue y currentSection.

currentKeyValue

Obtiene el entero almacenado en la key recibida.

let currentKeyValue = settings.get_int(KEY);

Por ejemplo, si: KEY = "show-media" y GSettings contiene: show-media = 2 entonces: currentKeyValue = 2

currentSection

Y aquí tenemos justo lo que sospechábamos.

let currentSection = KEY.substring(5,KEY.length);

La cadena: "show-media" tiene:

s h o w -
0 1 2 3 4

substring(5, ...) empieza en el índice 5, por lo que elimina: "show-" y queda: "media" Así:

show-media         → media
show-notification  → notification
show-events        → events

Esto es un pequeño detalle, pero muy útil para entender el diseño: la función recibe el nombre completo de la key y obtiene automáticamente el nombre de la sección.

Si el valor es 0, termina

Esto nos dice algo importante.

if(currentKeyValue == 0) {
    return;
}

El 0 probablemente representa: 0 = sección no mostrada, mientras que los valores 1, 2 y 3 representan posiciones. Todavía lo marcamos como interpretación, pero el código posterior prácticamente lo confirma.

show-notification = 2
show-events       = 3

Ahora podemos entender

El nombre de la función adjustOtherSectionsKeepingThisKeyValueSame(KEY) es largo, pero describe bastante bien lo que hace:

Ajustar las otras secciones manteniendo este valor de la key actual.

En otras palabras:

Usuario cambia una sección
        ↓
¿Otra sección tiene ahora el mismo número?
        ↓
Sí
        ↓
Encuentra el número disponible
        ↓
Mueve la otra sección a ese número

Y aquí se confirma algo muy importante para nuestro mapa:

show-media, show-notification y show-events no son simplemente flags booleanos.

Son enteros que representan el orden de las secciones:

show-notification
show-events

        ↓

0 = no mostrar
1 = primera posición
2 = segunda posición

reorderOrderOfSections: function()

Esta función completa la lógica que veníamos siguiendo. Y aquí aparece claramente para qué existe sections-order.

reorderOrderOfSections: function() { ... }

Su función es tomar los valores numéricos de:

show-media
show-notification
show-events

Y convertirlos en un arreglo ordenado de nombres que se guarda en: sections-order.

sections-order

Crea una estructura temporal

let orderStr = ["noValue","noValue","noValue"];

Tenemos tres posiciones posibles:

orderStr
│
├── [0] → primera posición
├── [1] → segunda posición
└── [2] → tercera posición

Inicialmente ninguna está ocupada: ["noValue", "noValue", "noValue"]. noValue funciona como marcador temporal de posición vacía.

Obtiene las posiciones actuales

let mediaNotificationEventsSectionOrder = [
  settings.get_int("show-media"),
  settings.get_int("show-notification"),
  settings.get_int("show-events")
];

Por ejemplo:

show-media        = 2
show-notification = 1
show-events       = 3

Produce: [2, 1, 3]. Recordemos nuestra interpretación:

0 → no mostrar
1 → primera
2 → segunda
3 → tercera

Coloca media en su posición

if(mediaNotificationEventsSectionOrder[0]!=0){
  orderStr[mediaNotificationEventsSectionOrder[0]-1] = "media";
}

Supongamos: show-media = 2. Entonces: 2 - 1 = 1 y: orderStr[1] = "media";

Resultado: ["noValue", "media", "noValue"].

Hace lo mismo con notification

if(mediaNotificationEventsSectionOrder[1]!=0){
  orderStr[mediaNotificationEventsSectionOrder[1]-1] = "notification";
}

Si: show-notification = 1 queda: ["notification", "media", "noValue"].

Y finalmente events

if(mediaNotificationEventsSectionOrder[2]!=0){
  orderStr[mediaNotificationEventsSectionOrder[2]-1] = "events";
}

Si: show-events = 3 obtenemos: ["notification", "media", "events"]

Ahora aparece: let tempOrderStr=[]; y:

Es decir, sections-order no parece ser el origen de la configuración; más bien es un resultado derivado de show-media, show-notification y show-events.
