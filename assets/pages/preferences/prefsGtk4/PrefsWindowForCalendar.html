prefSwitchInverted: function(KEY, pos)

Aquí encontramos la implementación que faltaba y ahora podemos entender perfectamente qué significa prefSwitchInverted().

La diferencia fundamental respecto a prefSwitch() es el !.
prefSwitchInverted: function(KEY, pos) {

  let SettingSwitch = new Gtk.Switch({
      hexpand: false,
      active: !settings.get_boolean(KEY),
      halign: Gtk.Align.END
  });

  SettingSwitch.connect("notify::active", Lang.bind(this, function(button) {
      settings.set_boolean(KEY, !button.active);
      reloadExtension();
  }));

  this.attachLabel(KEY,pos);
  this.attach(SettingSwitch, 1, pos, 1, 1);

},

Al crear el Switch

El normal hacía: 
active: settings.get_boolean(KEY)
Mientras que este hace: 
active: !settings.get_boolean(KEY)

Es decir, invierte el valor.

Si GSettings contiene: KEY = true el switch aparece: active = false

Y si contiene: KEY = false aparece: active = true

Podemos representarlo:

GSettings              Switch

true       ── ! ──→    OFF
false      ── ! ──→    ON

Cuando el usuario mueve el Switch

Aquí vuelve a aparecer la inversión:

settings.set_boolean(KEY, !button.active);

Por ejemplo, si el usuario activa el switch: button.active = true se guarda:

KEY = !true
    = false

Si lo desactiva: button.active = false se guarda:

KEY = !false
    = true

Por tanto:

Switch               GSettings

ON        ── ! ──→   false
OFF       ── ! ──→   true

¿Por qué hacer esto?

Porque probablemente la key representa una condición negativa: 

show-events-section-if-empty

En ese caso, tendría sentido invertir la representación.

El nombre de la configuración dice:

"Mostrar la sección de eventos si está vacía".

Pero quizás la interfaz que se quiere presentar al usuario sea conceptualmente:

"Ocultar la sección de eventos cuando está vacía".

Pero ojo: eso último es una hipótesis basada en el nombre. Lo que podemos afirmar con certeza es únicamente que la interfaz y el valor almacenado están deliberadamente invertidos.

Observaciones

Esta clase prácticamente funciona como una declaración de qué opciones debe mostrar la página Calendar. No contiene la lógica de cada preferencia. Esa responsabilidad está repartida:

PrefsWindowForCalendar
        │
        │ "quiero mostrar esta preferencia"
        ▼
PrefsWindow_NotificationCenter
        │
        │ "así se construye un Combo/Switch..."
        ▼
GSettings

Y prefSwitchInverted() es una herramienta adicional para los casos donde la representación del Switch debe ser la inversa del valor almacenado.

¿Cómo funciona?

prefSwitchInverted() funciona así:

                 prefSwitchInverted(KEY)
                         │
             ┌───────────┴───────────┐
             ▼                       ▼
      leer GSettings            crear Switch
             │                       │
             │                    !valor
             │                       │
             └───────────────────────┘
                         │
                    usuario cambia
                         │
                         ▼
                  guardar !active
                         │
                         ▼
                   reloadExtension()
