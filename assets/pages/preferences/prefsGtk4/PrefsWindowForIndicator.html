prefComboInt: function(KEY, pos, options, items)

Pasamos a la siguiente función, que además confirma nuestra sospecha sobre autohide.

Crea un Gtk.ComboBoxText, igual que prefCombo().

prefComboInt: function(KEY, pos, options, items) {

    let SettingCombo = new Gtk.ComboBoxText();

La diferencia fundamental estará en cómo se lee y se guarda el valor.

Construcción de las opciones

for (let i = 0; i < options.length; i++) {
    SettingCombo.append(options[i], items[i]);
}

Exactamente el mismo patrón:

options[i] → identificador/valor
items[i]   → texto visible

Por ejemplo, para autohide:

options                    items

"0"  ───────────────────→  "No"
"1"  ───────────────────→  "Yes"
"2"  ───────────────────→  "If Do Not Disturb is Off"

Aquí está la diferencia importante

SettingCombo.set_active(settings.get_int(KEY));

prefCombo() utilizaba: settings.get_string(KEY). Pero prefComboInt() utiliza: settings.get_int(KEY)

Por tanto podemos confirmar:

prefComboInt() está destinado a GSettings keys de tipo entero (int).

Y además set_active() espera justamente un índice de opción, por lo que aquí el valor entero almacenado funciona directamente como índice.

Ejemplo:

GSettings:
autohide = 2

       ↓

set_active(2)

       ↓

Combo selecciona:
"If Do Not Disturb is Off"

Cuando el usuario cambia la opción

SettingCombo.connect('changed', Lang.bind(this, function(widget) {
    settings.set_int(KEY, widget.get_active());
    reloadExtension();
}));

widget.get_active() devuelve el índice:

No                         → 0
Yes                        → 1
If Do Not Disturb is Off   → 2

Y ese índice se guarda directamente:

widget.get_active()
        ↓
settings.set_int(KEY, ...)

Después: reloadExtension(); Así que cualquier cambio provoca una recarga de la extensión.

Finalmente, crea la etiqueta y coloca el ComboBox

Esto es exactamente igual que en prefCombo().

this.attachLabel(KEY,pos);
this.attach(SettingCombo, 1, pos, 1, 1);

prefCombo() vs prefComboInt()

Ahora tenemos una distinción muy clara:

prefCombo()
│
├── Gtk.ComboBoxText
├── settings.get_string(KEY)
├── settings.set_string(KEY, ...)
└── valores almacenados → STRING
prefComboInt()
│
├── Gtk.ComboBoxText
├── settings.get_int(KEY)
├── settings.set_int(KEY, ...)
└── valores almacenados → INTEGER

Y esto explica perfectamente el uso anterior:

this.prefComboInt(
    "autohide",
    pos++,
    ['0','1','2'],
    [...]
);

Aunque options contiene strings, lo que realmente se almacena en GSettings es el índice entero:

autohide = 0
autohide = 1
autohide = 2

Comparación de los tres métodos que acabamos de descubrir

CONTROL GSettings
prefSwitch() Gtk.Switch boolean
prefCombo() Gtk.ComboBoxText string
prefComboInt() Gtk.ComboBoxText integer
prefInt() Gtk.SpinButton integer
prefTime() Gtk.SpinButton integer

Y ahora podemos volver a displayPrefs() de Indicator y completar los dos elementos que antes estaban pendientes:

indicator-index
    └── prefInt()
        └── entero 0–20

autohide
    └── prefComboInt()
        └── entero 0–2

Una pequeña observación para prefTime() y prefInt() son técnicamente muy parecidos —ambos terminan almacenando un entero mediante un SpinButton—, pero tienen rangos diferentes según el propósito. Con esto ya tenemos identificados los métodos auxiliares necesarios para entender esta clase.

La Herencia de PrefsWindow

Tenemos tres páginas que reutilizan la misma clase base:

                    PrefsWindow_NotificationCenterExtension
                                  │
                     ┌────────────┼────────────┐
                     │            │            │
                     ▼            ▼            ▼
                 Calendar     Indicator    AppList

Todas heredan los métodos auxiliares:

attachLabel()
prefCombo()
prefStr()
prefSwitch()
prefSwitchInverted()
prefTime()
prefComboInt()
prefInt()

Esto nos permite ver mejor la intención del diseño original: la clase PrefsWindow_NotificationCenterExtension es principalmente una clase base para construir las distintas páginas de preferencias, mientras que Calendar, Indicator y AppList se encargan de decidir qué preferencias mostrar.

Y algo que ya empieza a ser importante para nuestro futuro trabajo de modernización: tenemos identificados claramente qué nombres pertenecen al diseño original y cuáles son simplemente herramientas reutilizables, así que cuando llegue el momento de renombrar NotificationCenterExtension, podremos hacerlo de forma mucho más controlada.
