Mapas de INSTALL.sh

Ahora que terminamos de recorrer todo INSTALL.sh, podemos hacer los mapas.

La idea central del flujo

Podemos resumir todo el script en cinco grandes etapas:

1. Configurar
      ↓
2. Preparar destino
      ↓
3. Limpiar instalación anterior
      ↓
4. Instalar + compilar recursos
      ↓
5. Informar resultado

Aquí lo organizaría de una manera diferente al flujo, porque el mapa mental busca mostrar qué responsabilidades tiene el script, no necesariamente el orden exacto.

Su relación con la estructura de la extensión

Esto nos permite ver algo que antes estaba un poco disperso:

INSTALL.sh no forma parte del funcionamiento interno de la extensión, solo es una herramienta auxiliar de instalación.

La extensión necesita:

  • extension.js
  • prefs.js
  • metadata.json
  • stylesheet.css
  • schemas/
  • locale/
  • etc.

Pero INSTALL.sh existe para preparar y colocar esos recursos en el lugar donde GNOME Shell los espera.

Ahora podemos colocar INSTALL.sh dentro de todo lo que hemos aprendido del proyecto:

                         PROYECTO
                            │
             ┌──────────────┼──────────────┐
             │              │              │
             ▼              ▼              ▼
       extensionDir       locale         schemas
             │              │              │
             │              │              │
             │              ▼              ▼
             │             .po        .gschema.xml
             │              │              │
             │            msgfmt    glib-compile-schemas
             │              │              │
             │              ▼              ▼
             │             .mo      gschemas.compiled
             │              │              │
             └──────────────┼──────────────┘
                            │
                            ▼
                     INSTALL.sh
                            │
                            ▼
               ~/.local/share/gnome-shell/
                       extensions/
                            │
                            ▼
                extensión instalada

Ahora tenemos además una referencia externa muy útil: el ZIP real de la versión publicada. Así, podremos contrastar lo que hace el script con lo que efectivamente termina dentro del paquete.

Aquí encaja perfectamente nuestro descubrimiento del ZIP. El paquete  descargado desde extensions.gnome.org contenía:

notification-center@Selenium-H/
├── extension.js
├── prefs.js
├── ...
├── locale/
│   ├── it/
│   │   ├── notification-center.po
│   │   └── LC_MESSAGES/
│   │       └── notification-center.mo
│   └── nl/
│       ├── notification-center.po
│       └── LC_MESSAGES/
│           └── notification-center.mo
│
└── schemas/
    ├── org.gnome.shell.extensions.notification-center.gschema.xml
    └── gschemas.compiled

Ahora sabemos qué representan esos archivos:

.po                 → fuente de traducción
.mo                 → catálogo compilado para gettext

.gschema.xml        → definición del esquema GSettings
gschemas.compiled   → esquema compilado

Y sabemos que INSTALL.sh puede generar esos artefactos localmente.
