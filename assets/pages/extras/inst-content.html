Contenido de INSTALL.sh

Este primer bloque todavía no instala ni modifica nada. Solo establece las variables que el resto del script utilizará.

Shebang

#!/bin/bash

Indica que este archivo debe ejecutarse utilizando Bash.

No es simplemente un comentario. El #! es el shebang, y le dice al sistema qué intérprete debe utilizar cuando ejecutamos el script directamente, por ejemplo:

./INSTALL.sh

En este caso:

INSTALL.sh
    │
    ▼
/bin/bash
    │
    ▼
ejecuta las instrucciones

Versión del script

#Version 4
#=========

Son comentarios y no tienen ningún efecto durante la ejecución.

El autor está indicando que esta es la versión 4 de INSTALL.sh. Importante: esto no necesariamente corresponde a la versión de la extensión. Es decir, no debemos interpretar: Version 4 como: Notification Center v4.

Es la versión del instalador. Lo podemos considerar simplemente información de mantenimiento para el desarrollador.

Directorio predeterminado de instalación

# Default Installation Directory
installDir=~/.local/share/gnome-shell/extensions

Nuevamente tenemos un comentario descriptivo y después una variable: installDir que contiene: 

~/.local/share/gnome-shell/extensions

El ~ representa el directorio HOME del usuario que ejecuta el script.

Por ejemplo, en tu sistema: 

~
└── /home/mgue
Por lo que conceptualmente:
~/.local/share/gnome-shell/extensions
Equivale a:
/home/dev/.local/share/gnome-shell/extensions

El propósito de esta variable es evitar repetir toda la ruta posteriormente.

En lugar de hacer:
cp algo ~/.local/share/gnome-shell/extensions
El script puede utilizar:
cp algo $installDir

Así, si alguna vez cambia el directorio de instalación, solamente tendría que modificarse la variable.

Nombre de la extensión

# Extension Name and directory
extensionName=notification-center

Aquí aparece otra variable: extensionName con el valor:  notification-center.

Y aquí encontramos algo que ya conocemos de nuestro estudio de extension.js.

Recordemos:

ExtensionUtils.initTranslations("notification-center");

Tenemos el mismo identificador: notification-center.

Pero todavía no debemos asumir que todas las apariciones tienen exactamente la misma función. En este contexto concreto, el nombre se está utilizando como nombre base de la extensión/archivos relacionados con ella.

Por ejemplo, más adelante vimos que el instalador genera: notification-center.mo  precisamente a partir de: $extensionName. Así que esta variable también sirve para evitar escribir repetidamente: notification-center.

Directorio de la extensión

extensionDir=$extensionName@Selenium-H

Aquí tenemos: extensionDir y su valor se construye utilizando la variable anterior:

extensionName
    │
    ▼
notification-center
    │
    │ + @Selenium-H
    ▼
notification-center@Selenium-H

Este nombre nos resulta especialmente importante porque GNOME Shell identifica las extensiones mediante su UUID. En este proyecto antiguo, el UUID es: notification-center@Selenium-H y eso explica por qué el instalador necesita distinguir: extensionName de extensionDir.

Son dos conceptos diferentes:

Variable Valor Función
installDir ~/.local/share/gnome-shell/extensions Dónde se instalan las extensiones
extensionName notification-center Nombre/base utilizado por el proyecto
extensionDir notification-center@Selenium-H Directorio/UUID de esta extensión

Podemos visualizarlo así:

installDir
│
└── ~/.local/share/gnome-shell/extensions/
        │
        └── extensionDir
              │
              └── notification-center@Selenium-H/

Este bloque ya empieza a darle comportamiento real al instalador. Aquí aparecen dos conceptos importantes de Bash: argumentos del script y códigos de salida.

Salto de línea

echo ""

Simplemente imprime una línea vacía en la terminal. No afecta la lógica del instalador; es únicamente presentación.

¿Se proporcionó un primer argumento?

if [ ! -z $1 ]
then
    installDir=$1
fi

Aquí aparece $1, en Bash, $1 significa:

El primer argumento que recibió el script.
Por ejemplo: 
./INSTALL.sh /otra/ruta
Entonces: 
$1 = /otra/ruta
El if pregunta:
[ ! -z $1 ]
Que conceptualmente significa:
"¿$1 NO está vacío?"
Si existe un primer argumento, el script reemplaza: 
installDir=~/.local/share/gnome-shell/extensions
Por: 
installDir=$1

Por tanto, tenemos:

             ¿se proporcionó $1?
                    │
             ┌──────┴──────┐
             │             │
            NO            SÍ
             │             │
             ▼             ▼
     usa valor       installDir=$1
     predeterminado

Esto nos dice algo interesante, el directorio que vimos en el bloque anterior no está realmente fijo, es un valor predeterminado y el usuario puede proporcionar otro directorio.

Entonces el instalador preguntará al usuario, pero si $2 tiene algún valor, no pregunta.

El else es: Si el usuario proporcionó un segundo argumento, el script lo utiliza directamente como respuesta.

Por ejemplo:

Así que no necesita preguntarnos nada. Esto permite dos formas de utilizar el instalador:

Interactiva: el script pregunta.

Con parámetros: el script utiliza directamente los valores proporcionados.

Pregunta si la respuesta fue exactamente: y

Si es así, mkdir, crea un directorio y -p significa que también puede crear los directorios padre que hagan falta.

mkdir -p $installDir

Por ejemplo, si no existiera: ~/.local/share/gnome-shell/extensions, mkdir -p puede crear la cadena necesaria.

Comprueba si mkdir tuvo éxito

Este es un concepto muy importante en Bash. $? contiene el código de salida del último comando ejecutado. Justamente antes ejecutamos:

Por lo que ahora: $? contiene el resultado de mkdir.

Normalmente: 
0 = éxito
otro valor = error
Por eso: 
[ $? -eq 0 ]

significa:

"¿El comando anterior terminó correctamente?"

Otra línea vacía

Simplemente deja separación visual.

Mensaje sin salto de línea

Aquí aparecen dos opciones de echo:

Evitar el salto de línea al final (-n)

Normalmente: 
echo "Hola"

Produce:

En nuestro caso esto permite que el siguiente comando se ejecute en la misma línea visual.

Secuencias especiales (-e)

Permite interpretar secuencias especiales como \n, \t, etc.

En este texto concreto, no parece haber ninguna secuencia especial que necesite -e, así que aquí probablemente es innecesario pero no afecta al resultado de este mensaje.

Elimina la versión anterior

rm -rf $installDir"/"$extensionDir

Aquí está la parte importante: rm significa remove. Las opciones:

-r significa recursive: elimina directorios y todo su contenido.

-f significa force: no pregunta antes de eliminar y, en general, ignora ciertos errores como que el archivo no exista.

La ruta que construye es: 
$installDir
    +
"/"
    +
$extensionDir
Por defecto: 
~/.local/share/gnome-shell/extensions/
    +
notification-center@Selenium-H

Resultando en:

~/.local/share/gnome-shell/extensions/notification-center@Selenium-H

Es decir:

Borra completamente la instalación anterior de notification-center@Selenium-H, si existe.

¿Por qué rm -rf y no simplemente copiar encima?

Esto es bastante importante para entender la filosofía del instalador.

El autor no hace: 
copiar archivos nuevos
        ↓
sobrescribir archivos existentes
Hace: 
instalación anterior
        │
        ▼
     eliminar
        │
        ▼
instalación limpia
        │
        ▼
     copiar nueva

Eso evita que queden archivos antiguos que ya no formen parte de la nueva versión. Por ejemplo, imaginemos que una versión vieja tenía:

extension/
├── extension.js
├── prefs.js
└── old-file.js
Y la nueva versión solamente tiene: 
extension/
├── extension.js
└── prefs.js
Si simplemente copiáramos encima: 
extension/
├── extension.js
├── prefs.js
└── old-file.js    ← ¡quedaría!

Con: rm -rf ... primero se elimina todo y luego se instala nuevamente.

extension/
      ↓
    vacío

Eso produce una instalación más limpia.

Finalmente

echo "Done"

Como el echo anterior utilizó -n, este mensaje aparece en la misma línea:

Removing any Older Version ...   Done

Por tanto, visualmente el bloque completo produce algo parecido a:

Installing Extension notification-center@Selenium-H
Installation Path ~/.local/share/gnome-shell/extensions

Removing any Older Version ...   Done

Y aquí aparece una característica importante de este instalador:

Cada instalación comienza eliminando completamente la instalación anterior.

¿Por qué utiliza $extensionName?

break es importante

break

No termina todo el script, solo termina el for actual. Por ejemplo:

de  → OK
it  → OK
ko  → ERROR
nl  → NO se procesa

Es decir, ante el primer error de compilación el script deja de intentar generar más traducciones y continuará con las instrucciones que estén fuera del for.

Si msgfmt falló en alguno de los idiomas status="Error" entonces el script informa: Extension Installed, Translations not done.

Esto es bastante importante porque nos revela la filosofía del instalador:

Un error al generar las traducciones no hace que la instalación completa sea considerada fallida.

La extensión ya fue instalada; simplemente las traducciones no quedaron preparadas correctamente, es decir, tenemos dos estados independientes:

Instalación de extensión
        │
        ├── realizada
        │
        ▼
Traducciones
        │
        ├── OK
        │
        └── Error

Por eso el mensaje dice explícitamente: 

Extension Installed,
Translations not done.

No dice:

Installation failed.

Primera instrucción: Restart GNOME Shell

El autor indica el procedimiento histórico:

Alt + F2
r
Enter

Esto era particularmente relevante en las versiones antiguas de GNOME Shell donde ese procedimiento permitía reiniciar GNOME Shell sin cerrar la sesión. 

No debemos asumir que ese procedimiento sigue siendo válido para las versiones modernas que estamos buscando soportar; eso será una cuestión para nuestra futura fase de modernización.

Por ahora solamente registramos:

El instalador fue escrito pensando en un entorno de GNOME Shell donde el reinicio mediante Alt + F2 → r → Enter era una operación disponible.
Segunda instrucción: Enable this extension using GNOME Tweak Tool.

El instalador no habilita la extensión automáticamente, su responsabilidad termina después de instalarla. El usuario debe posteriormente habilitarla mediante GNOME Tweak Tool.
