_onOpenStateChanged()

_onOpenStateChanged(menu, open)

Antes de leer el código, preguntémonos:

¿Cuándo debería ejecutarse?

Solo por el nombre, yo diría:

"Cuando el menú cambia de estado (abierto o cerrado)."
Y el parámetro: 
open
Seguramente sea un booleano. 
 true  -> se abrió 
 false -> se cerró

Ahora leamos el primer bloque

if (!open) {
    this.resetIndicator();
    this.remove_style_pseudo_class('active');
    return;
}

Me gusta mucho. Aquí dice:

"Si el menú se está cerrando..."

Entonces:

  • reinicia el indicador;
  • quita el estilo visual "activo";
  • termina.

Es una salida temprana (early return). A mí me gustan mucho porque evitan tener un enorme:

if (open) {
   ... 
}

envolviendo todo el método.

Después viene la parte interesante

Main.panel.statusArea.dateMenu._calendar.setDate(new Date());

Aquí ya empezamos a ver algo importante. La extensión está reutilizando el calendario original de GNOME. No crea uno nuevo, simplemente le dice:

"Actualízate a la fecha actual."

Eso refuerza algo que ya sospechábamos:

Notification Center modifica componentes existentes.

Luego

this.add_style_pseudo_class('active');

Esto me gusta mucho porque complementa perfectamente el disable. 

Cuando el menú abre: 
activo
Cuando cierra: 
no activo

Es muy coherente.

Después

this.manageEvents(0);

No sabemos qué hace, pero el nombre ya nos dice bastante. Probablemente:

"Actualizar el estado de los eventos."

Esta línea

[
 this.mediaSection.visible,
 this.notificationSection.visible
] =
[
 this.mediaSection._shouldShow(),
 this.notificationSection._list.get_children().length
];

Aquí sí tuve que leer dos veces. Porque utiliza una característica muy bonita de JavaScript. Está haciendo una asignación múltiple, es una sintaxis elegante. Equivale más o menos a:

this.mediaSection.visible =
    this.mediaSection._shouldShow();

this.notificationSection.visible =
    this.notificationSection._list.get_children().length;

Después

Solo el nombre ya me hizo sonreír. Porque cuenta una historia completa. Existe un icono que puede parpadear. Y cuando abrimos el menú... deja de parpadear. Tiene mucho sentido desde el punto de vista de la experiencia de usuario.

this.blinkIconStopIfBlinking();

Luego

if(!this.showLabel) {
    ...
}

Aquí todavía no sabemos qué es showLabel. Pero entendemos la intención, perfectamente razonable. Si no se muestran etiquetas... reinicia los contadores.

Finalmente

this.seenEvents = true;
this.resetIndicator();

Aquí el método termina dejando claro:

"El usuario ya vio los eventos."

Eso me parece una decisión de diseño muy lógica.
