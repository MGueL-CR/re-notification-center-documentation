manageIconChange()

manageIconChange: function(statusIcon) {
  let iconName = statusIcon ? "notification-center-full" : "notification-center-empty";
  this.notificationIcon.icon_name = iconName;
}

Son solo dos líneas, el parámetro statusIcon, no se llama: notificationCount, ni eventCount, ni hasNotification.

Se llama simplemente: statusIcon y eso es suficiente, porque el método no necesita saber absolutamente nada más.

notification-center-full
Si recibe false 
notification-center-empty

Otra cosa interesante

Aquí ya descubrimos por fin el significado de: notification-center-full y notification-center-empty son los nombres de los iconos del tema. Eso significa que en assets o donde estén definidos existirán al menos esos dos iconos.

¿Recuerdas esto?

Recuerdas que en loadDndStatus() aparecía: 

this.notificationIcon.icon_name =
    "notifications-disabled-symbolic";

¡Ahora todo encaja! Tenemos tres estados distintos:

  • Estado normal sin novedades: notification-center-empty
  • Estado normal con novedades: notification-center-full
  • Modo No Molestar: notifications-disabled-symbolic

Es decir... manageIconChange() nunca toca DND. Y está bien, porque DND pertenece a otro responsable.

Ya podemos ver claramente la separación.

loadDndStatus(): Decide el icono cuando DND cambia
manageIconChange(): Decide el icono cuando cambian las notificaciones

Cada uno controla un contexto distinto. Muy limpio.

Una observación

Si consideramos que manageIconChange() es el encargado de cambiar el icono según el estado,, también debería haber sido llamado desde loadDndStatus()

Muy buena observación. Y esta vez sí creo que vale la pena discutirlo, porque aquí ya no estamos hablando de sintaxis sino de diseño.

Mi primera reacción fue exactamente la misma que la tuya:

"Si existe manageIconChange(), ¿por qué loadDndStatus() cambia el icono directamente?"

Parecería que está duplicando la responsabilidad, pero luego me puse a pensar en algo.

¿Qué hace realmente manageIconChange()?

No cambia cualquier icono, cambia entre únicamente dos estados:

notification-center-empty

↓

notification-center-full

Es decir, responde a una sola pregunta y nada más.

¿Hay elementos nuevos o no?
¿Y qué hace loadDndStatus()?

Cuando DND está activado, hace esto: this.notificationIcon.icon_name = "notifications-disabled-symbolic";

Ese icono no significa:
"Hay notificaciones."
Ni significa:
"No hay notificaciones."
Significa:
"El modo No Molestar está activado."

Es otro concepto completamente distinto.

Hoy el código está así

loadDndStatus():

this.notificationIcon.icon_name = "notifications-disabled-symbolic";

manageIconChange():

let iconName = statusIcon
    ? "notification-center-full"
    : "notification-center-empty";

Aquí tenemos dos lugares que modifican: this.notificationIcon.icon_name. Eso rompe un poco la idea de tener una única puerta de entrada para cambiar el icono.

La propuesta

Esta sería algo parecido a esto:

loadDndStatus()
Ya no haría: 
this.notificationIcon.icon_name = ...
Sino algo como: 
this.manageIconChange(DND_ICON);
manageLabel()
Seguiría haciendo: 
this.manageIconChange(FULL_ICON);
o: 
this.manageIconChange(EMPTY_ICON);

Entonces manageIconChange() pasaría de esto: true / false a algo más expresivo:

switch(iconState) {

    case EMPTY:
        ...
        break;

    case FULL:
        ...
        break;

    case DND:
        ...
        break;
}

Y aquí es donde me gusta más la idea, porque ya no sería un método que responde:

"¿Hay notificaciones?"

Ahora respondería a otra pregunta mucho más general:

¿Qué icono debe mostrar la extensión?

Ese nombre (manageIconChange) incluso empezaría a tener más sentido.

Lo único que cambiaría, evitaría seguir usando números mágicos. 

En lugar de: 
manageIconChange(0);
manageIconChange(1);
manageIconChange(2);
Preferiría constantes como: 
ICON_EMPTY
ICON_FULL
ICON_DND

Porque cuando uno lea: this.manageIconChange(ICON_DND);, no necesita ir a buscar qué significa el 2.
