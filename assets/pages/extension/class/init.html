_init()

Selenium-H decidió que el constructor fuera el lugar donde el objeto se prepara por completo, pero sin iniciar todavía la extensión.

Eso ya nos dice algo. El ciclo de vida parece ser:

>enable()
    │
    ▼
new NotificationCenter()
    │
    ▼
_init()        ← prepara todo
    │
    ▼
startNotificationCenter()  ← comienza a modificar GNOME

Dividamos el constructor

Bloque 1: Preparación básica

ExtensionUtils.initTranslations(...);
this.prefs = ExtensionUtils.getSettings(...);
this.parent(...);

Aquí hay tres cosas distintas.

1. Traducciones

ExtensionUtils.initTranslations(...)

Le dice a la extensión:

"A partir de ahora puedes usar _() para traducir textos."

Eso explica por qué más abajo aparece:

_("Clear")

2. Configuración

this.prefs = ExtensionUtils.getSettings(...)

Ya carga GSettings. Eso significa que desde el constructor cualquier método podrá hacer:

this.prefs.get_boolean(...)
this.prefs.get_int(...)

Sin volver a buscar la configuración.

3. Herencia

this.parent(...)

¿NotificationCenter hereda de alguien? Y la respuesta es:

Extends: PanelMenuButton

Eso significa que NotificationCenter es un botón del panel. Esto cambia bastante la vista de la arquitectura.

No contiene un botón. Es el botón.

Es decir:

"NotificationCenter es una versión especializada de un PanelMenuButton."

¿Recuerdas que hablamos de JavaScript moderno?

Aquí aparece otra traducción mental y esta representa la herencia entre clases.

En GJS antiguo: 
this.parent(...)
En JavaScript moderno equivale a: 
super(...)

Bloque 2: Obtener referencias de GNOME

Ahora viene un bloque enorme.

this._messageList = ...
this.eventsSection = ...

etc.

No está creando nada. Está diciendo:

"Necesito saber dónde están las cosas de GNOME."

Es decir, está guardando referencias. Por ejemplo:

this._messageList

Seguramente apunta a la lista de notificaciones que ya existe en GNOME. No crea una nueva, sino que obtiene la existente.

Eso es muy importante. Porque esta extensión no reemplaza completamente el centro de notificaciones, más bien, lo reutiliza.

Bloque 3: Cargar preferencias

this.loadPreferences();

Aquí apareció un método muy interesante. No sabemos qué hace, pero el nombre es excelente. Probablemente lea todas las preferencias y las copie a propiedades del objeto.

Bloque 4: Variables de estado

Después aparecen muchísimas líneas como:

this.connectedSignals = [];

... 

this.notificationCount = 0;

... 

this.isDndOff = true;

Aquí Selenium-H está inicializando el estado interno del objeto. No hace acciones, simplemente deja todo listo.

Bloque 5: Crear widgets

Aquí ya empezamos a ver ST.

new St.Icon(...)		// crea un icono del panel.

... 

new St.Label(...)		// crea una etiqueta.

... 

new St.BoxLayout(...)		// crea un contenedor.

... 

new St.Button(...)		// crea un botón.

Esto sí me gusta muchísimo. Porque ahora ya sabemos para qué sirve ST. No es teoría, estamos viendo como crea los widgets.

Bloque 6: Scroll

Aquí aparece: 
new St.ScrollView(...)
y después: 
Main.panel.statusArea.dateMenu.menu.box.style = ...

Todavía no vamos a analizarlo. Solo anotar que aquí ya empieza a modificar el aspecto visual.

Bloque 7

Las dos últimas líneas ya son detalles visuales.

this.add_style_class_name(...)
this.notificationIcon.set_pivot_point(...)
