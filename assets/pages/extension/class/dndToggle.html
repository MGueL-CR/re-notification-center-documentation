dndToggle()

dndToggle: function() {

    this.dndpref.set_boolean('show-banners',!this.dndpref.get_boolean('show-banners'));

  }

Lo primero que me llamó la atención, no hay:

  • if
  • switch
  • for
  • try
  • llamadas a otros métodos

Solo una línea.

this.dndpref.set_boolean(
    'show-banners',
    !this.dndpref.get_boolean('show-banners')
);

Lo que hace es elegantísimo, si lo descomponemos:

Primero lee el valor actual 
this.dndpref.get_boolean('show-banners')

Supongamos que devuelve true después hace ! es decir:

!true
↓

false

Y finalmente lo vuelve a guardar: set_boolean(...).

Dibujémoslo:

Caso 1 
show-banners = true
↓

leer
↓

true
↓

!
↓

false
↓

guardar
↓

show-banners = false
Caso 2 
show-banners = false
↓

leer
↓

false
↓

!
↓

true
↓

guardar
↓

show-banners = true

Es literalmente un interruptor.

Y aquí descubrimos otra cosa fíjate que dndToggle()... No sabe absolutamente nada de la interfaz. No conoce:

  • iconos
  • etiquetas
  • opacidad
  • animaciones
  • menú

Solo conoce una cosa: La preferencia de GNOME y eso me parece un excelente diseño.

Cada método tiene una responsabilidad, si lo ponemos junto a los otros dos:

Responsabilidad de middleClickDndToggle():

Detectar el clic central.

Responsabilidad de dndToggle():

Cambiar el valor de la preferencia.

Responsabilidad de loadDndStatus():

Reflejar ese estado en toda la interfaz.

Eso significa que el flujo está perfectamente dividido.

Usuario
↓

middleClickDndToggle()
↓

dndToggle()
↓

loadDndStatus()

Cada método hace una sola cosa y la hace bien.
