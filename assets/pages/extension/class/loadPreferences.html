loadPreferences()

loadPreferences: function() {

    this.autohide                     = this.prefs.get_int("autohide");
    this.mediaSectionToBeShown        = (this.prefs.get_int("show-media")>0)?true:false;
    this.notificationSectionToBeShown = (this.prefs.get_int("show-notification")>0)?true:false;
    this.eventsSectionToBeShown       = (this.prefs.get_int("show-events")>0)?true:false;
    this.eventsSectionPosition        = this.prefs.get_enum("events-position");  // 0 = below, 1 = dont show, 2 = beside
    this.hideEmptySpace               = this.prefs.get_boolean("autohide-space-beside-calendar");
    this.showEventsInCalendarAlso     = (this.eventsSectionToBeShown && this.eventsSectionPosition != 1) ? true: false;
    this.showEventsSectionIfEmpty     = this.prefs.get_boolean("show-events-section-if-empty"); 
    this.showThreeIcons               = this.prefs.get_boolean("individual-icons");
    this.includeEventsCount           = this.prefs.get_boolean("include-events-count");
    this.newNotificationAction        = this.prefs.get_enum("new-notification");
    this.eventsSectionhere            = this.showEventsInCalendarAlso;
    this.showingSections              = this.prefs.get_strv("sections-order");
    this.appBlackList                 = this.prefs.get_strv("name-list");
    this.scriptList                   = this.prefs.get_strv("script-list");
    this.allowRunningScript           = this.prefs.get_boolean("run-script");
    this.blackListAction              = this.prefs.get_enum("for-list"); 
    this.notAnimateIcon               = !this.prefs.get_boolean("animate-icon");
    this.blinkTime                    = this.prefs.get_int("blink-time");
    this.blinkCount                   = this.prefs.get_int("blink-icon")*2;
    this.showLabel                    = this.prefs.get_boolean("show-label");
    this.changeIcons                  = this.prefs.get_boolean("change-icons");  

  }

Este método:

  • No toma decisiones.
  • No mueve widgets.
  • No conecta señales.
  • No modifica la interfaz.

Hace una sola cosa:

Leer todas las preferencias del usuario y guardarlas en memoria.

Es como cuando un programa inicia y carga su archivo de configuración.

this.showLabel

...

A partir de ese momento, el resto de la extensión ya no tiene que preguntar constantemente al gschema. Solo consulta las propiedades del objeto, eso es mucho más eficiente y hace el código más legible.

Hay un patrón muy claro, la mayoría de las líneas son simplemente:

this.algo = this.prefs.get_xxx(...)

Por ejemplo:

this.autohide = this.prefs.get_int("autohide");
this.showLabel = this.prefs.get_boolean("show-label");

No hay misterio, solo está creando una "fotografía" de la configuración actual.

Ahora sí, vamos por grupos

Porque creo que aquí Selenium-H organizó las preferencias por temas.

1. Autohide

this.autohide = this.prefs.get_int("autohide");

Ya sabemos que después existe: manageAutohide(). Así que esta variable será la materia prima de ese método.

2. Secciones visibles

Aquí aparece un grupo muy interesante.

this.mediaSectionToBeShown
this.notificationSectionToBeShown
this.eventsSectionToBeShown

Me gusta que el nombre sea tan descriptivo.

No dice: 
showMedia
Dice literalmente:
"La sección de medios debe mostrarse."

Es muy fácil leer después un código como: if (this.mediaSectionToBeShown)

Un detalle curioso:
(this.prefs.get_int(...) > 0) ? true : false;

Aquí tengo una pequeña observación.

Esto ya devuelve un booleano. Es decir true o false.

(this.prefs.get_int("show-media") > 0)

Entonces el operador ternario: ? true : false es redundante. Podría haberse escrito simplemente:

this.mediaSectionToBeShown =
    this.prefs.get_int("show-media") > 0;

El resultado sería exactamente el mismo. No es un error, simplemente es una forma más verbosa.

3. Posición de eventos

this.eventsSectionPosition =

// 2 = beside

7. Scripts

allowRunningScript

Esto me llamó la atención porque confirma que la extensión puede ejecutar scripts definidos por el usuario. Todavía no sabemos cómo, pero sabemos que existe esa posibilidad.

8. Animación

this.notAnimateIcon =
    !this.prefs.get_boolean("animate-icon");

Aquí está nuestra vieja conocida, me hizo gracia el nombre.

No guarda: 
animateIcon
Guarda: 
notAnimateIcon

Y para obtenerlo hace una negación. Funciona perfectamente, pero personalmente creo que habría sido más claro guardar directamente: this.animateIcon y evitar el ! mental cada vez que se lea el código.

No está mal, es simplemente una decisión de estilo.

9. Parpadeo

Sin sorpresa con this.blinkTime, Pero con...

this.blinkCount =
    this.prefs.get_int("blink-icon") * 2;

Aquí sí levanto una ceja. ¿Por qué multiplicar por dos? No lo sabemos todavía. 

Y justamente por eso no voy a inventar una explicación. Puede que más adelante encontremos un: while(blinkCount--) o que cuente encendidos y apagados. De momento, solo anotaría la duda.

En resumen

Diría que loadPreferences() es como leer un archivo config.ini al arrancar una aplicación.

No hace absolutamente nada más que cargar datos, ni una sola llamada como a: manage... Ni una modificación visual, solo deja el objeto preparado.

Destacar un detalle de diseño

¿Recuerdas que en loadDndStatus() dijimos que existía un "único punto de verdad" para sincronizar el estado DND? Aquí veo la misma filosofía.

En lugar de tener por todo el código cosas como: this.prefs.get_boolean("show-label") repetidas una y otra vez... Selenium-H decidió concentrarlas aquí.

Eso tiene varias ventajas:

  • Si cambia el nombre de una clave del gschema, probablemente solo haya que modificar este método.
  • El resto del código queda más limpio, porque trabaja con propiedades como this.showLabel o this.changeIcons en lugar de conocer los detalles del almacenamiento.
  • También facilita la lectura: cuando más adelante veamos if (this.showLabel), ya sabremos que ese valor proviene de una preferencia cargada al iniciar.

Creo que esta función cumple exactamente el papel que esperábamos: no hace nada espectacular, pero prepara el terreno para que todas las demás funcionen de forma ordenada. Es uno de esos métodos que rara vez llaman la atención, pero cuyo diseño influye en toda la arquitectura de la extensión.
