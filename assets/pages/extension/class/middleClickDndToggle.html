Observaciones

¿Por qué escucha button-press-event si solo le interesa el botón central?

Esta sigue siendo una muy buena pregunta, el código nos dice:

this.actor.connect('button-press-event', ...);

Para luego:

switch(event.get_button()) {
    case 2:
        ...
}

Lo único que podemos afirmar, GNOME le entrega todos los clics mediante ese evento, después, Selenium-H decide cuál le interesa. Hasta aquí, es un hecho.

¿Existía un evento solo para el botón central?

Podemos plantear varias posibilidades:

Hipótesis A:

GNOME/GObject simplemente ofrece un único evento: button-press-event

Y el botón se consulta mediante: event.get_button()

Si eso es así... No había otra opción.

Hipótesis B: 

Sí existe otra forma, pero Selenium-H prefirió esta porque es el patrón habitual en GTK/GNOME.

Hipótesis C:

Existía otra forma, pero en GNOME 40 no funcionaba correctamente o era menos portable.

¿Cuál creo hoy?

Después de haber visto bastante código de esta extensión... Me inclino todavía más por la Hipótesis A.

¿Por qué?

Porque Selenium-H reutiliza muchísimo la API de GNOME, no da la impresión de ser alguien que haga rodeos innecesarios. Si hubiera existido un elegante: middle-button-press-event me sorprendería que no lo hubiera usado.
