El nombre era: animateOnNewNotification() y yo pensaba que iba a contener varios if, varios ease() y quizá algún temporizador.

Pero no, tiene una idea muy clara:

Construir una animación mediante recursión.

Eso me sorprendió gratamente.

animateOnNewNotification: function(times, op=254, angle=3)

Ya nos da tres pistas:

times: Es evidente, controla cuántos pasos de la animación quedan.

op: op = 254. Esto es la opacidad y va disminuyendo poco a poco.

angle: angle = 3. No mueve únicamente el icono, también lo inclina.

[ this.visible, this.notificationIcon.visible ] = [ true, true ];

Muy lógico, antes de animar... Asegúrate de que exista algo para ver.

if(times == 0 || this.notAnimateIcon)

Esto es prácticamente un algoritmo recursivo clásico. Si ya no quedan pasos... o el usuario desactivó las animaciones... termina.

Pero terminar no significa detenerse en seco, hace una última animación:

scale_x: 1.0
scale_y: 1.0
translation_y: 0
opacity: 255
rotation_angle_z: 0

Es decir... Devuelve el icono exactamente a su estado normal. Eso evita que quede torcido, agrandado o semitransparente.

Y entonces aparece el enlace con el resto del grupo

onComplete:
    this.blinkIcon(...)

¡Ya encontramos al segundo integrante del equipo!

this.notificationIcon.ease(...)

Ahora viene la parte que más me gustó. Cuando todavía quedan pasos, hace una animación hacia:

El icono crece:

scale_x: 1.2
scale_y: 1.2

Sube unos píxeles: translation_y: -4

Se inclina: rotation_angle_z: angle

Y aquí aparece un detalle muy bonito: El signo cambia.

Mira esto: -angle eso significa que hará algo como:

+3°

↓

-3°

↓

+3°

↓

-3°

No gira siempre hacia el mismo lado. Oscila, eso hace que la animación parezca mucho más natural.

También baja la opacidad: op-1 No creo que visualmente se note muchísimo, pero sí hace que cada paso tenga un ligero cambio.

Lo mejor de todo, aquí está la llamada recursiva.

this.animateOnNewNotification(
    --times,
    op-1,
    -angle
)

Cada ease() termina llamando al siguiente. No necesita:

  • timers,
  • loops,
  • intervalos.

La propia animación encadena la siguiente.

¿Por qué existe otro método para el parpadeo?

Y esto responde la duda, porque este no hace el parpadeo. Hace una especie de... animación de entrada. Después entrega el control a: blinkIcon().

Una observación para el futuro

Este es uno de esos métodos donde sí veo posible modernizar un poco el código, pero sin cambiar el comportamiento.

Por ejemplo, los números:

150
1.2
-4
3
254
255

Son "números mágicos". Más adelante podríamos pensar en constantes con nombres descriptivos, algo como:

ANIMATION_DURATION
ICON_SCALE
ICON_BOUNCE
ICON_ROTATION

No porque el código esté mal, sino porque facilitaría ajustar la animación sin buscar valores sueltos por el método. 

const ICON_SCALE = 1.2;
const ICON_ROTATION = 3;
const ICON_TRANSLATION_Y = -4;
const ICON_ANIMATION_DURATION = 150;

El comportamiento seguiría siendo idéntico, pero el código sería más expresivo.
