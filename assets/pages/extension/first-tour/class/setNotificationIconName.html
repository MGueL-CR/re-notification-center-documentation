setNotificationIconName()

setNotificationIconName: function () {
    if(Gtk.IconTheme.get_default()) {
      this.notificationIconName =
          Gtk.IconTheme.get_default().has_icon("notification-symbolic")
          ? "notification-symbolic"
          : "preferences-system-notifications-symbolic";
    }
    else {
      this.notificationIconName = "preferences-system-notifications-symbolic";
    }
}

Lo primero que descubrimos, ¡Que ya resolvimos una parte del misterio de los iconos!

Mira el nombre que busca: "notification-symbolic" y si no existe... usa: "preferences-system-notifications-symbolic"

¡Esos sí son claramente iconos del sistema GNOME! Entonces... Aquí se cae una de mis teorías anteriores. Yo pensaba que:

notification-center-full
notification-center-empty

Podían formar parte del mismo mecanismo, pero ahora veo que no. Este método utiliza únicamente iconos estándar de GNOME.

¿Qué está haciendo realmente?

Gtk.IconTheme.get_default().has_icon(...)

Hace una comprobación muy elegante, es decir:

"¿El tema actual tiene este icono?"

Si sí... úsalo. Si no... usa otro. Eso hace la extensión mucho más compatible entre distintas versiones o temas de iconos.

¿Por qué existe notificationIconName?

this.notificationIconName

No cambia el icono inmediatamente, simplemente guarda: notification-symbolic o preferences-system-notifications-symbolic para que otro método lo utilice.

Y efectivamente... ¿Quién lo usa? Nuestro viejo conocido: loadDndStatus(). ¿Cuando? Aquí: 

this.notificationIcon.icon_name =
    this.notificationIconName;

Ahora todo encaja perfectamente.

Lo curioso

Fíjate en la responsabilidad.

setNotificationIconName()

↓

¿Qué nombre debo usar?
loadDndStatus() ↓ ¿Cuál debo mostrar ahora?

Son dos preguntas completamente distintas y por eso están separadas.

Hay algo más

Mira este código: if(Gtk.IconTheme.get_default()) Luego: has_icon(...) Y si no existe un tema... todavía tiene un valor por defecto.

preferences-system-notifications-symbolic

Eso demuestra que Selenium-H estaba pensando en no dejar nunca la variable sin inicializar.

Observación de diseño

Además, me gusta mucho que este método no toque el widget. Solo hace: this.notificationIconName = ... Nada más.

Eso significa que incluso puede ejecutarse varias veces sin producir efectos visuales inmediatos. Después otro método decidirá cuándo aplicar ese nombre, es un detalle pequeño, pero hace que el código sea más limpio.

Conclusión del método

Es otro ejemplo perfecto del estilo de Selenium-H: métodos cortos, con una única responsabilidad y sin efectos secundarios innecesarios y además nos deja una investigación pendiente muy interesante:

¿Dónde salen notification-center-full y notification-center-empty?

Porque ahora sabemos con certeza que no pertenecen al mismo mecanismo que notification-symbolic.
