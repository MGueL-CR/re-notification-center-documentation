Enable()

Este enable() es muchísimo más pequeño de lo que esperaba. Esto me dice que Selenium-H quiso que enable() fuera un orquestador , no un lugar donde vive toda la lógica. 

    function enable() {

notificationCenter = new NotificationCenter();
notificationCenter.startNotificationCenter();
reloadExtensionOnPrefsChange();
reloadApplicationProfilesOnPrefsChange();

}

Analicemos línea por línea

    notificationCenter = new NotificationCenter();

Se crea el objeto principal, pero fíjate en un detalle... No hace nada más, todavía no inicia la extensión.

    notificationCenter.startNotificationCenter();

Y aquí vino la sorpresa. Yo esperaba que el constructor hiciera toda la inicialización. pero Selenium-H separó dos conceptos, que  me parece una decisión interesante.

Iniciar el objeto

Esto significa que el constructor probablemente solo prepara el objeto. Mientras que startNotificationCenter() es quien realmente:

  • crea el panel,
  • registra señales,
  • modifica GNOME.

Es un patrón bastante limpio.

    startNotificationCenter()

Este nombre me encanta. No necesito ver el código para imaginar qué hace. Probablemente:

"Si el usuario cambia una preferencia, reinicia la extensión."
    reloadApplicationProfilesOnPrefsChange();

Aquí descubrimos algo que ni siquiera sabíamos que existía, Application Profiles . Eso significa que la extensión tiene un sistema de perfiles, ni siquiera habíamos llegado a esa parte del código.
