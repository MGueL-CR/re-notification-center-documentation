Configuración DND

Y aquí ocurre exactamente lo mismo que vimos con el botón Clear, pero aplicado al No molestar (Do Not Disturb - DND).

switch(this.prefs.get_enum("dnd-position")) {
  case 1:
    this.dndItem._delegate = this;
    this.dndItem.connect("toggled", ()=>this.dndToggle());
    this._messageList._dndSwitch.visible = false;
    this._messageList._dndButton.label_actor.visible = false;
    this.menu.box.insert_child_at_index(new PopupMenu.PopupSeparatorMenuItem(), 0);
    this.menu.box.insert_child_at_index(this.dndItem, 0);
    break;

  case 2:
    this.dndItem.connect("toggled", ()=>this.dndToggle());
    this._messageList._dndSwitch.visible = false
    this._messageList._dndButton.label_actor.visible = false
    this.menu.box.add_child(new PopupMenu.PopupSeparatorMenuItem());
    this.menu.box.add_child(this.dndItem);
}

Lo primero que vemos:

this.prefs.get_enum("dnd-position")

Ya conocemos este patrón. El usuario, desde las preferencias, eligió dónde quiere que aparezca el interruptor de No molestar. Todavía no hemos visto el gschema, pero podemos imaginar algo así: 

0 = Original
1 = Arriba
2 = Abajo

No sabemos si esos son exactamente los valores, pero el switch nos dice que existen, al menos, las opciones 1 y 2.

No molestar

Selenium-H no escribió dos implementaciones distintas. Reutilizó casi todo, solo cambia la forma de insertar el widget, eso hace que el código sea fácil de mantener.

Ahora viene un bloque que me parece especialmente interesante. 

Después del switch aparece: 

this.loadDndStatus();
this.resetIndicator();

Son solo dos líneas, pero sospecho que representan un cambio de fase:

  • Hasta ahora hemos construido el Notification Center.
  • A partir de aquí empezamos a sincronizarlo con el estado real del sistema.

Y tengo muchas ganas de ver qué hace loadDndStatus(), porque por el nombre parece uno de esos métodos que no crea nada, sino que lee el estado actual de GNOME y adapta la interfaz de la extensión. Tengo la impresión de que será otro buen ejemplo de cómo Selenium-H reutiliza el sistema en lugar de reemplazarlo. 

Observa estas dos líneas:

this.loadDndStatus();
this.resetIndicator();
No hacen esto: 
this.dndItem.visible = true;
this.notificationCount = 0;
Ni tampoco: 
let estado = this.loadDndStatus();

Simplemente:

this.loadDndStatus();

Eso ya nos dice algo sobre esos métodos (lo que podemos deducir), hay dos tipos de métodos muy comunes.

Tipo 1: Métodos que devuelven información

Esperamos que nos devuelvan un valor:

let icon = this.getNotificationIcon();
let enabled = this.isDndEnabled();

Tipo 2: Métodos que realizan una acción

No esperamos un resultado, esperamos que ellos mismos modifiquen el estado del objeto y loadDndStatus() me transmite justamente eso.

this.loadPreferences();
this.startNotificationCenter();
this.undoChanges();
