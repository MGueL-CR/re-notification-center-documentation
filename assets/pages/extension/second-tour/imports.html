Imports, Constantes y variables globales

Encabezado de versión

Es simplemente un comentario.

/*
Version 24.02
=============

*/

Pero tenemos que hacer una distinción importante respecto a current-version.

Aquí:Version 24.02 es información escrita por el desarrollador en el código. No significa que JavaScript esté obteniendo la versión desde ahí.

Más adelante vimos que existe:Metadata.version que es otra cosa. Por ahora:

Comentario
└── Version 24.02
    └── informativo

Lo dejamos anotado porque durante la modernización probablemente tendremos que revisar si este comentario coincide con la versión real de la extensión.

ExtensionUtils

Importamos el módulo de utilidades de extensiones de GNOME.

const ExtensionUtils = imports.misc.extensionUtils;

Este será importante porque normalmente mediante ExtensionUtils se obtiene información de la extensión, preferencias, settings, etc.

Ya vimos anteriormente que el código utiliza conceptos relacionados con:ExtensionUtils.getSettings(...) por lo que esta dependencia probablemente estará conectada directamente con nuestro gschema.

Gtk

Aquí se importa GTK.

const Gtk = imports.gi.Gtk;

Pero atención: estamos en:extension.js no en prefsGtk4.js. Eso significa que GTK está siendo utilizado desde la parte principal de la extensión, algo que tendremos que observar.

No asumimos todavía para qué.

LangClass

Esto pertenece al sistema antiguo de clases de GNOME/GJS.

const LangClass = imports.lang.Class;

Y aquí encontramos algo que ya conocemos perfectamente porque lo vimos en prefsGtk4.js:new GObject.Class(...).

Pero aquí es:LangClassasí que probablemente encontraremos código del estilo antiguo:

const NotificationCenter = new LangClass({
    ...
});

O algo equivalente.

Esto será especialmente interesante durante la modernización porque las clases antiguas basadas en imports.lang son precisamente una de las cosas que tendremos que evaluar.

Por ahora:

LangClass
└── sistema de clases antiguo de GJS

Main

Esta es una dependencia muy importante.

const Main = imports.ui.main;

Main representa una parte central del entorno de GNOME Shell. Y ya vimos en nuestro primer recorrido que la extensión hace cosas como:

Main.panel
Main.notify(...)

Así que tenemos:

extension.js
   │
   └── Main
       ├── Main.panel
       ├── Main.notify()
       └── ...

Aquí seguramente vamos a tener muchas conexiones en el mapa de dependencias.

MetaKeyBindingFlags

Esto importa las banderas relacionadas con atajos/teclas y bindings de teclado de Mutter/GNOME Shell.

const MetaKeyBindingFlags = imports.gi.Meta.KeyBindingFlags;

Por el nombre, podemos sospechar que tendrá relación con:indicator-shortcut que vimos en gschema y prefsGtk4.js. ¡Pero todavía no afirmamos que sea así!

La conexión hipotética sería:

gschema
   │
   └── indicator-shortcut
             ?
             ▼
      MetaKeyBindingFlags
             │
             ▼
       extension.js

Cuando encontremos dónde se utiliza MetaKeyBindingFlags, comprobaremos si efectivamente existe esa relación.

PanelMenuButton

Esto ya nos da una pista enorme sobre la clase principal.

const PanelMenuButton = imports.ui.panelMenu.Button;

Recordemos que anteriormente vimos:NotificationCenter y sabíamos que era un elemento integrado en el panel de GNOME. Aquí encontramos la dependencia que probablemente permite construirlo:

PanelMenuButton
       │
       ▼
NotificationCenter
       │
       ▼
GNOME Shell panel

Más adelante seguramente veremos algo parecido a:Extends: PanelMenuButtony entonces podremos confirmar la relación.

PopupMenu

Esto nos indica que la extensión trabaja con menús emergentes de GNOME Shell.

const PopupMenu = imports.ui.popupMenu;

Y esto encaja perfectamente con lo que ya sabemos:

Notification Center
        │
        ▼
menú desplegable
        │
        ├── calendario
        ├── notificaciones
        ├── eventos
        └── controles

Por tanto:

PopupMenu
└── infraestructura de menús de GNOME Shell

Todavía veremos exactamente qué clases o funciones utiliza.

ShellActionMode

Esto tiene relación con los modos de acción de GNOME Shell, especialmente para determinar en qué contexto pueden ejecutarse determinadas acciones o bindings.

const ShellActionMode = imports.gi.Shell.ActionMode;

De nuevo, probablemente esté relacionado con el acceso mediante teclado. Pero no lo damos por hecho hasta encontrar su uso.

St

St es Shell Toolkit, el toolkit visual utilizado históricamente por GNOME Shell.

const St = imports.gi.St;

Esto es importantísimo porque significa que extension.js construye/modifica elementos visuales directamente usando St.

Por ejemplo, posteriormente podríamos encontrar:

new St.BoxLayout(...)
new St.Label(...)
new St.Icon(...)

Así que tenemos otra rama del mapa:

GNOME Shell UI
     │
     ├── St
     ├── PopupMenu
     └── PanelMenuButton

utilSpawn

Este es uno que debemos marcar.

const utilSpawn = imports.misc.util.spawn;

Ya habíamos dejado como pendiente la cuestión de:

script-list / ejecución de scripts.

Y ahora aparece:utilSpawnEsto es una pista muy fuerte. Recordemos que prefsGtk4.js permite configurar:

application-list
name-list
script-list
run-script

y que script-list contiene rutas a scripts. Ahora aparece:

prefsGtk4.js
    │
    └── script-list
            │
            ▼
      extension.js
            │
            ▼
        utilSpawn

Este es exactamente el tipo de conexión que buscábamos en este segundo recorrido. Todavía no sabemos exactamente cómo se ejecuta ni bajo qué condiciones. Pero ya tenemos una dependencia concreta que debemos seguir.

Traducciones

const _ = imports.gettext
    .domain("notification-center")
    .gettext;

Esto conecta directamente con algo que ya vimos al estudiar la estructura del proyecto:

locale/
├── de
├── it
├── ko
├── nl
└── notification-center.pot

La función _() es la encargada de obtener la traducción correspondiente.

Por eso encontramos cosas como estas en todo el código.

_("Notifications")
_("Calendar")
_("Reset Notification Center to defaults?")

Mapa:

locale/
   │
   ▼
gettext domain
   │
   ▼
notification-center
   │
   ▼
_()
   │
   ▼
texto traducido

Esto confirma algo que ya habíamos entendido en prefsGtk4.js.

Variable global

Aquí tenemos algo diferente.

let notificationCenter = null;

No es una dependencia sino estado global del módulo.

Inicialmente: notificationCenter = null

Probablemente más adelante ocurra algo como:notificationCenter = new NotificationCenter(...); y entonces este objeto represente la instancia activa de la extensión.

Esto es importante porque debemos investigar:

  • quién lo asigna;
  • quién lo consulta;
  • quién lo destruye;
  • si puede haber más de una instancia;
  • qué ocurre durante enable() / disable().
