Aquí aparece una parte bastante importante: cómo la extensión calcula el tamaño de su área de notificaciones y cómo adapta ese tamaño a la escala de pantalla de GNOME.

Obtiene el factor de escala

let scaleFactor =
    St.ThemeContext.get_for_stage(global.stage).scale_factor;

scale_factor representa la escala que GNOME está aplicando a la interfaz.

Por ejemplo, conceptualmente:

escala normal → 1
escala HiDPI  → 2

No debemos asumir que solo existen esos dos valores, pero la idea es esa.

La extensión necesita ese valor porque más adelante hace: this._messageList.width / scaleFactor

Es decir, está convirtiendo el ancho de _messageList al sistema de coordenadas que necesita para definir el tamaño del ScrollView.

Crea el ScrollView

this.scrollView = new St.ScrollView({
    hscrollbar_policy: 2,
    style:
        "min-width:" +
        (this._messageList.width / scaleFactor) +
        "px;" +

        "max-height: " +
        0.01 * this.prefs.get_int("max-height") *
        Main.layoutManager.monitors[0].height +
        "px;" +

        "max-width: " +
        (this._messageList.width / scaleFactor) +
        "px;" +

        "padding: 0px;"
})

Aunque la línea es larga, conceptualmente está haciendo esto:

ScrollView
│
├── ancho mínimo = ancho de _messageList / escala
├── ancho máximo = ancho de _messageList / escala
├── alto máximo  = porcentaje de altura del monitor
└── padding      = 0
El ancho

Es importante porque el ancho no viene de una preferencia.

this._messageList.width / scaleFactor

Viene directamente del componente de GNOME Shell:

_messageList.width
       │
       ▼
   / scaleFactor
       │
       ▼
   ScrollView

Así que la extensión intenta mantener el ancho de su centro de notificaciones relacionado con el ancho de la lista original de GNOME.

max-height es realmente un porcentaje

Aquí tenemos una conexión directa con prefsGtk4.js. Recordemos:

this.prefTime("max-height", pos++, 20, 100, 1);

Por tanto el usuario puede seleccionar algo entre: 20 ... 100. Pero el código hace: 0.01 * this.prefs.get_int("max-height"). Así que convierte el número a una fracción.

Por ejemplo:

Preferencia Cálculo Resultado
20 0.01 × 20 0.20
50 0.01 × 50 0.50
75 0.01 × 75 0.75
100 0.01 × 100 1.00

Después: 0.01 * max-height * monitorHeight

Por ejemplo, si el monitor mide 1080px y max-height = 50:

0.01 × 50 × 1080
= 540 px

Por eso max-height realmente significa:

Porcentaje de la altura del monitor que puede ocupar el área de notificaciones.

Y ahora tenemos una relación directa:

gschema
   │
   └── max-height
          │
          ▼
     prefsGtk4.js
          │
          │ SpinButton 20–100
          ▼
      extension.js
          │
          ▼
   porcentaje × altura monitor
          │
          ▼
      ScrollView

El pivote del icono

Aquí tenemos algo visual.

this.notificationIcon.set_pivot_point(0.5, 0);

El pivot_point determina desde qué punto se considera el origen para transformaciones como rotación o escala.

Los valores:

x = 0.5
y = 0

Representan aproximadamente:

        0 ───────────── 1
        ┌───────────────┐
      0 │       ●       │
        │      /        │
        │     /         │
      1 │               │
        └───────────────┘

O sea:

  • 0.5 → centro horizontal
  • 0 → parte superior

Esto probablemente tiene relación con alguna animación del icono. Y tenemos una pista muy buena porque en nuestro mapa de métodos ya aparecían:
