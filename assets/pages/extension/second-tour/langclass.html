Esta función es relativamente corta, pero conecta conteos, new-notification, eventos y cambio de iconos. Además, ahora que conocemos loadPreferences(), podemos leerla casi directamente.

notificaciones ──► nCount ──┐

Aparece el indicador de notificaciones

Así que esta línea realmente implementa:

Si está habilitado, llama: this.manageIconChange(...) Y le pasa: nCount > 0 || eCount > 0

Es decir, un booleano: 

hay notificaciones
       OR
hay eventos
       ↓
¿hay algo nuevo?

Por tanto podemos anotar:

nCount/eCount

manageLabel()

             │
             ▼
      manageIconChange(hayAlgo)

Todavía no debemos adelantarnos a qué hace manageIconChange(). Esa será la siguiente pieza que necesitamos estudiar.

Si está configurado "Show Count".

if (this.newNotificationAction == 2) {

Aquí separamos el caso:

newNotificationAction = 2
        ↓
Show Count

Entonces:

if(nCount > 0) {
    this.notificationLabel.text = nCount.toString();
}

El punto: • que fue creado en _init(): 

this.notificationLabel = new St.Label({
    text: "•",

Se convierte en algo como: 5 si hay cinco notificaciones.

Lo mismo para eventos:

if(eCount > 0) {

Así que tenemos la transformación:

new-notification
       │
       ├── 0 → nada
       ├── 1 → •
       └── 2 → número

Una cosa que ahora podemos descartar

Antes podríamos haber pensado que newNotificationAction solamente controlaba qué texto poner.

No.

La función demuestra que controla dos cosas:

  1. si el indicador es visible;
  2. qué representa visualmente.

Por eso:

0 → visible = false
1 → visible según conteo + punto
2 → visible según conteo + número
Y una pequeña observación de código

Estas expresiones:

nCount * this.newNotificationAction

y:

eCount * this.newNotificationAction

dependen de la conversión implícita entre números y booleanos.

Funciona, pero es menos expresivo que algo como:

nCount > 0 && this.newNotificationAction > 0

No lo cambiaría todavía, exactamente por la misma razón que hicimos con (!this.isDndOff) * this.autohide > 1: primero estamos reconstruyendo el comportamiento histórico; después podremos decidir qué conviene modernizar.
